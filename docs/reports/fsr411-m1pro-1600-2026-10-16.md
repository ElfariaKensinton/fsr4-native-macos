# FSR 4.1.1 Lite on M1 Pro at 1600p

## Ultra Performance cadence fix

The M1–M4 Lite cadence had two gates that excluded the performance-focused
3x path: it rejected Ultra Performance, and it only reused inference at up to
2x output scale. For a 2560×1600 output and the rounded 853×533 render size,
Lite therefore ran the full neural network on every frame. The cadence now
allows one-frame temporal reuse up to 3x, including the 1–2 pixel rounding
shortfall used by common 3x presets. Reset frames and consecutive reuse are
still rejected.

The M1 Pro benchmark used the same generated 8-frame scene, 2560×1600 output,
853×533 input, Ultra Performance model, and `int8-simd` backend. Each run had
one warmup sequence and 12 measured sequences (96 frames):

| Build | Mean GPU time per upscaled frame | Neural/reused frames |
| --- | ---: | ---: |
| Lite reuse disabled | 24.371 ms | 96 / 0 |
| Lite reuse enabled | 15.243 ms | 48 / 48 |

That is **37.5% less FSR command-buffer time** (1.60× standalone upscaler
throughput) on this same-device A/B. It measures the FSR path only, not total
game FPS.

To inspect temporal differences, an 8-frame synthetic moving-scene comparison
between Lite reuse and full inference measured 29.97 dB PSNR. The frames were
visually close in that test; this is a frame-difference metric, not a ground-
truth image-quality score or an in-game result.

## Earlier 2x profile check

An earlier 1280×800 → 2560×1600 run measured 43.78 ms for `exact-fast` and
28.23 ms for Lite. A separate hook log captured `exact-fast`, but that log
does not establish which profile was used during the user's A/B test. The
3x cadence exclusion above is a code-path explanation for why Lite could
produce no speedup with an Ultra Performance render scale.
